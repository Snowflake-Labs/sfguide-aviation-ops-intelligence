## Friction Points

### F1: COMPONENT tag allowed values too restrictive

- **Step:** 6d: TSA Throughput
- **Severity:** Low
- **What happened:** The COMPONENT tag only allows `[etl, analytics, realtime, backfill, properties]`. The TSA throughput skill reference suggested `tsa-throughput` as a component value, which is not in the allowed list.
- **Resolution:** Used `etl` as the COMPONENT tag value for TSA tasks instead.
- **Recommendation:** Either add `tsa-throughput` to the COMPONENT tag ALLOWED_VALUES list in base-setup, or update TSA throughput references to explicitly use `etl`.

---

### F2: FLIGHT_SCHEDULE schema mismatch between adsb-ingestion and derived-analytics

- **Step:** 6e: Derived Analytics
- **Severity:** Low
- **What happened:** The HELPER_LANDING_LIVE_TIMETABLE view references `FLIGHT_STATUS` column, but the FLIGHT_SCHEDULE table (created by adsb-ingestion) uses `STATUS` instead.
- **Resolution:** Adapted the view to alias `STATUS AS FLIGHT_STATUS`.
- **Recommendation:** Standardize FLIGHT_SCHEDULE column naming across adsb-ingestion and derived-analytics reference files. Either rename the column to `FLIGHT_STATUS` in adsb-ingestion or update derived-analytics references to use `STATUS`.

---

### F3: Podman registry login fails with --password-stdin

- **Step:** 6f: Dashboard (React/SPCS)
- **Severity:** Low
- **What happened:** `podman login $REGISTRY -u 0sessiontoken --password-stdin` failed silently. The `--creds` flag approach worked on subsequent push.
- **Resolution:** Used `podman push --creds "0sessiontoken:$TOKEN"` directly, which succeeded.
- **Recommendation:** The build-images.md reference already documents this fallback. Consider making `--creds` the primary approach for podman to avoid the login step entirely.

---

### F4: snow CLI connection name not auto-detectable

- **Step:** 6f: Dashboard (React/SPCS)
- **Severity:** Low
- **What happened:** The build-images.md references `-c <connection>` but the installer doesn't track which snow CLI connection name to use. Tried `wgb26798` (account name) which failed; had to search for the correct connection name `fleet_test_evals`.
- **Resolution:** Used `snow connection list` to find the correct connection name.
- **Recommendation:** Add a step early in the installer workflow to detect the snow CLI default connection via `snow connection list` and store it as `{SNOW_CONNECTION}` for use in SPCS deployment steps.
